# MurCMS 0.4.2

Дата: 2026-11-07

Редакторы страниц, категорий и snippets начинают работу с заголовка/имени и содержимого. Сохранение страниц и snippets использует POST/303/GET с возвратом к тому же объекту. Общие компактные строки настроек, прокручиваемые таблицы, доступные icon actions и адаптивные формы применяются ядром.

- Snippets 1.1.0: четыре вкладки (Редактор, Мои сниппеты, Системные, Загрузка файла), front matter для parser/murtext.* и расширяемых ключей, все действия над локальными системными файлами, ссылки областей и radio для загрузки. Сохраняются language → global → default и остановка fallback черновиком. Интегрирован ранее подготовленный snippets.render/registry.
- SEO главной: title/description каждого языка в seo.php → home; fallback каждого поля: язык → основной язык → site.name/site.description. Системное site.name остаётся общим.
- Updated_at: шесть контролов в timezone сайта, проверка календаря и DST gaps. Галочка по умолчанию снята, разрешает сохранить показанные значения; ручной ввод и «Сейчас» включают её. Без галочки прежняя дата сохраняется, отсутствующая создаётся при первом Save. В списке различаются metadata и файловый fallback. Sitemap использует корректный ISO lastmod, прежний date/mtime fallback сохранён; dist включает lastmod для новых сайтов, рабочий выбор не меняется. Article metadata выводится только при явном seo.type: Article, BlogPosting или NewsArticle.
- PHP-функции: super_admin-редактор /admin/template/functions, site-owned data/templates/{resolved-template}/functions.php, синтаксическая проверка без исполнения, CSRF, backup/restore, atomic write и запрет symlinks. Публичный require_once выполняется до шаблона; admin этот файл не загружает. PHP в snippets по-прежнему требует snippets.allow_php.
- Навигация: профиль по имени в topbar; frontend/admin favicons в соответствующих настройках при прежних runtime keys; управление плагинами первым пунктом группы Плагины даже при пустом enabled. Неисполняемый info.json безопасно показывает имя, ID, версию и описание.
- MurText integration 0.2.4: единая плотная справка с проверенными короткими DIV, details, таблицами и прочим синтаксисом. Полный канонический документ доставляется в plugin/help и доступен по /admin/plugin/murtext/help с admin role. Parser core остаётся 0.2.0.
- BerryMur 1.0.0 включён по дополнительному запросу в стандартную поставку без изменения предоставленного runtime-кода. CSS загружается локально после load/idle только при .mur-berry; noscript сохраняется. Зоны не предназначены для первого экрана.
- Banerina 0.1.1 распространяется отдельно: полная ширина таблицы, доступные icon actions/status, жирное количество и полный список snippets, включая 10+. Механика групп сохранена.

Стандартная CMS содержит восемь плагинов: snippets, blocks, gallery, tags, redirects, murconsent, murtext, berrymur. Baseline и источники версий описаны в [versioning reference](../development/versioning-release.md). Исторические notes 0.4.1 сохранены.

## Установка и обновление

Новая установка: MurCMS-0.4.2-root.zip, только root/, без рабочего administrator account. Скопируйте нужные dist-конфиги в рабочие и создайте уникального super_admin согласно [инструкции установки](../installation-update.md).

Существующий сайт: MurCMS-0.4.2-update.zip. Сначала backup и staging. Копируйте содержимое root/ поверх document root. Пакет не заменяет runtime config, content, storage, uploads, пользовательские CSS/functions и .htaccess. Защиты .htaccess поставляются отдельно для ручного сравнения; DELETE-PATHS.txt ничего не удаляет автоматически. Рабочий plugins.php сохраняется, поэтому BerryMur включается вручную. Уже установленная Banerina остаётся работоспособной и обновляется отдельным ZIP.

Отдельные plugin update ZIP содержат только code/assets/help/info.json и нужные dist defaults. Runtime murtext.php и banerina.php не заменяются. docs.zip распространяется отдельно. Сборка из зафиксированного commit создаёт package manifests, RELEASE-COMMIT.txt и SHA256SUMS.txt.

## Проверки

Repository scripts/test.ps1 включает PHP/JS lint, общий smoke, изолированные release-регрессии, проверки дат/BerryMur и MurConsent. scripts/build-release.ps1 проверяет ZIP paths, соответствие commit, восемь штатных плагинов, отсутствие Banerina в CMS packages и сохранение site-owned файлов при staged overlay. Browser QA проверяет реальные admin save/navigation и desktop/mobile.

Локальная проверка не заменяет [серверный checklist](../prerelease-checklist.md): Apache rewrite/AllowOverride, HTTPS, production config, GD/WebP или Imagick и реальные права файлов проверяются на целевом сервере. Lighthouse и внешние сервисы не входят в этот локальный проход. Фактические результаты конкретной сборки фиксируются в отдельном release report.
