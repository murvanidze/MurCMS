# MurCMS 0.1.0-rc.1

Date: 2026-07-08
Status: prerelease candidate snapshot

This snapshot totals the first near-release MurCMS state after the core/admin
audit, admin UX fixes, user-access work, template polish, documentation refresh,
and Parastas parity passes.

It is still a prerelease candidate, not a final public release. Public
deployment must pass `docs/prerelease-checklist.md` on the target server,
including production smoke checks, Apache `.htaccess` verification, Media
Manager upload checks, accessibility/Lighthouse checks, and a staging update
test.

## Main changes in this snapshot

- Admin user model with `super_admin`, `admin`, and `editor` roles.
- `/admin/settings/users` for user management with role hierarchy limits.
- Expanded admin profile with display name, e-mail, phone, language and
  password management.
- Session invalidation when a user is disabled, deleted, or has a changed
  password hash.
- Pages list language filter: default primary-language view and explicit
  all-language overview.
- Page bulk actions guarded against mixed-language selection.
- Multi-category assignment for pages and bulk page actions.
- Media Manager selection fixes, URL-list dialog behavior, ZIP download,
  move/delete bulk operations, and upload-time WebP conversion controls.
- Safer content, admin config, page delete and bulk delete backups.
- MurText plugin package included and enabled by default; native parsing remains the document default unless MurText settings or `parser: murtext` select it.
- Default template polish: theme schemes, frontend admin bar, favicons, brand
  handling, menu behavior, stable dimensions, and admin palette aligned with
  the MurCMS logo green.
- SEO/snippets/admin docs updated around robots, sitemap, `.htaccess`, snippets
  and access boundaries.
- Smoke tests expanded to cover admin roles, page/category behavior, media
  actions, assets, security guards and release-critical regressions.

## Distribution notes

For a root-only server package, build:

```powershell
.\scripts\build-root-pack.ps1
```

The resulting archive contains only source-controlled `root/` files, including
engine code, assets, templates, plugins, demo/starter data, `.dist.php` config
templates, `.htaccess`, upload protection and storage placeholders.

The archive intentionally excludes ignored local runtime files such as working
`root/data/config/*.php`, cache, logs, backups and local uploads.

## Verification baseline

Before marking this snapshot as done, run:

```powershell
.\scripts\test.ps1
```

For public release on a server, additionally run:

```powershell
php tests/smoke.php --production
```

The local development machine can fail `--production` for expected environment
reasons such as missing `mbstring`, missing GD/WebP support, local HTTP
`base_url`, or `environment => local`. Those are server-readiness blockers, not
necessarily code defects.
