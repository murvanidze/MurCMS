# MurCMS 0.4.1

Date: 2026-09-07
Status: stable patch release

MurCMS `0.4.1` is a maintenance release focused on update safety, plugin
packaging consistency, and documentation integrity. It does not introduce a
breaking Plugin API change relative to `0.4.0`.

## Main changes

- Consolidated current documentation into canonical `admin/`, `development/`,
  `plugins/`, and `releases/` sections while isolating the historical project
  brief under `archive/`.
- Added deterministic documentation anti-drift checks for canonical CMS/plugin
  versions, relative links, stable defaults and roles, package hygiene, and
  repository/root-package boundaries.
- Updated release packaging to read the CMS version from
  `root/murcms/app/version.php` instead of maintaining a hard-coded package
  version.
- Added a dedicated existing-site update pack that replaces engine, template,
  plugin code, and assets without overwriting runtime configs, site content,
  uploads, storage, or the working root `.htaccess`.
- Removed the shared usable administrator from `admin.dist.php`; new
  installations create a unique local `super_admin` config through an
  interactive password-safe repository script.
- Updated MurText integration to `0.2.3` and removed its duplicate plugin-local
  admin asset tree; the parser core remains `0.2.0`.
- Removed the development-only `example-footer-badge` plugin from the server
  root package.

## Updating an existing site

Build the update archive with:

```powershell
.\scripts\build-update-pack.ps1
```

Apply only the contents of the archive's `root/` directory over the installed
document root. Preserve working `data/config/*.php`, content, uploads, storage,
and the live root `.htaccess`. Review the supplied deletion manifest and merge
new `.htaccess` rules manually.

Before publishing to a server, complete
[`prerelease-checklist.md`](../prerelease-checklist.md) for the target environment.
