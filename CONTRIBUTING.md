# Contributing to MurCMS

Thank you for your interest in MurCMS.

At the current stage of the project, MurCMS accepts only:

- **bug reports**; and
- **feature requests**.

Please submit them through GitHub Issues.

MurCMS is **not currently accepting unsolicited Pull Requests, patches, or other code contributions to the Core**.

## Before Opening an Issue

Before opening a new Issue:

- search existing Issues to check whether the same bug or feature request has already been reported;
- keep each Issue focused on one bug or one feature request whenever possible;
- provide enough information for the issue to be understood without private context;
- do not include passwords, access tokens, credentials, private keys, personal data, confidential information, or private URLs unless they are strictly necessary and safe to disclose.

GitHub Issues are public unless GitHub explicitly indicates otherwise.

## Bug Reports

Bug reports are welcome.

A useful bug report should include, where relevant:

- the MurCMS version;
- the PHP version;
- the web server and hosting environment;
- the database type and version;
- the browser and operating system, if relevant;
- clear steps to reproduce the problem;
- the expected behavior;
- the actual behavior;
- relevant error messages or logs;
- screenshots or a minimal reproducible example, where useful.

Please describe what happened as precisely as possible. If the problem occurs only under particular conditions, include those conditions.

### Security Vulnerabilities

Do **not** publish exploit instructions, credentials, proof-of-concept attack code, or other sensitive vulnerability details in a public Issue.

If the repository provides GitHub's **Report a vulnerability** option, use that private reporting channel.

If no private reporting channel is available, open a public Issue asking for a private security contact method, but do not include technical vulnerability details in that Issue.

## Feature Requests

Feature requests and improvement suggestions are welcome.

A useful feature request should explain:

- the problem, limitation, or use case;
- the desired outcome or behavior;
- why the change would be useful;
- any relevant example or scenario.

A proposed technical solution may be included, but it is optional.

Please avoid combining unrelated feature requests in a single Issue.

Submitting a feature request does not guarantee that it will be accepted, implemented, or included in a future MurCMS release.

## Pull Requests and Code Contributions

MurCMS is not currently accepting unsolicited:

- Pull Requests;
- patches;
- code contributions to the Core.

If you believe the Core should be changed, please open a Bug Report or Feature Request and describe the problem or desired behavior instead.

Unsolicited Pull Requests may be closed without review.

The maintainer may request a code contribution in a specific case. Any such contribution will be handled under terms agreed separately before it is incorporated into the MurCMS Core.

This policy may change in the future.

## Other Requests

General support requests, installation assistance, hosting configuration questions, and other requests that are neither Bug Reports nor Feature Requests are outside the current scope of this repository and may be closed or redirected.
