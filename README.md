# MurCMS

MurCMS — легкая многоязычная flat-file CMS на PHP 8.5. Контент, меню,
блоки и настройки хранятся в файлах. MySQL и другая база данных не нужны.

Статус: стабильная версия `0.4.2`. Публикация на конкретном сервере требует
успешного production smoke-теста и
проверки на реальном Apache-сервере. Критерии описаны в
`docs/prerelease-checklist.md`.

Актуальная документация:

- `docs/current-reference.md` — фактическое устройство и возможности;
- `docs/ai-site-building-guide.md` — инструкция для ИИ по сборке новых сайтов;
- `docs/prerelease-checklist.md` — выпускной и серверный чек-лист;
- `docs/releases/0.4.2.md` — сводка текущей стабильной версии;
- `docs/plugins/murconsent.md` — установка и проверка MurConsent;
- `docs/README.md` — карта документации.

## Требования к серверу

- PHP 8.5;
- обязательные расширения PHP: `mbstring`, `session`, `json`, `GD` с WebP;
- рекомендуемые расширения: `Imagick`, `OPcache`, `zlib`;
- Apache 2.4 с `mod_rewrite`;
- рекомендуемые модули Apache: `mod_headers`, `mod_expires`, `mod_deflate`;
- document root сайта должен указывать на каталог `root/`, а не на корень
  репозитория.

GD является обязательным обработчиком изображений. Imagick поддерживается как
дополнительный более качественный конвертер и может быть установлен вместе с
GD.

## Структура публичного каталога

```text
root/
  murcms/    код движка, админка, плагины, шаблоны и assets
  data/      конфиги, страницы, категории, блоки, меню и snippets
  uploads/   загруженные пользователями файлы
  index.php
  .htaccess
```

`root/data` целиком закрыт от HTTP-доступа. В `root/murcms` публично доступны
admin/plugin assets и assets активного frontend-шаблона, например
`/murcms/templates/default/assets/...`. PHP-код движка, плагинов и шаблонов
закрыт правилами Apache и внутренними guard.

## Установка без установщика

1. Распакуйте дистрибутив в отдельный каталог и направьте document root
   виртуального хоста на `MurCMS/root`.
2. В `root/data/config/` скопируйте нужные файлы `*.dist.php` в файлы без `.dist`.
   Например, `site.dist.php` в `site.php`. Для нового `admin.php` используйте
   интерактивный `scripts/create-admin-config.ps1`, который не выводит пароль и
   отказывается перезаписывать существующий конфиг.
3. В `root/data/config/site.php` укажите публичный HTTPS-адрес, часовой пояс и
   `environment => production`.
4. Откройте `/admin/login` и войдите с уникальной учётной записью, созданной
   локально для этой установки.
5. Проверьте `/robots.txt`, `/sitemap.xml`, все языковые ветки и страницу 404.

Публичный дистрибутив намеренно не содержит общего логина и пароля. Скрипт
создаёт единственную локальную учётную запись `super_admin`; дополнительные
администраторы и редакторы создаются в `/admin/settings/users`.

## Права доступа

Веб-серверу нужен доступ на чтение к `root/` и доступ на запись к следующим
рабочим каталогам:

```text
root/data/config/
root/data/content/
root/data/blocks/
root/data/galleries/
root/data/menus/
root/data/snippets/
root/uploads/
root/data/storage/
root/.htaccess
```

Обычно на Linux применяют `0755` для каталогов только для чтения и `0644` для
файлов. Для изменяемых каталогов часто используют `0775` и добавляют
веб-сервер в нужную группу. Не используйте `0777`. Точные владелец и группа
зависят от хостинга.

`root/uploads/.htaccess` запрещает выполнение загруженных скриптов.
`root/.htaccess` закрывает прямой доступ к коду CMS, конфигам, Markdown-файлам
и резервным копиям. Для этих правил нужен Apache 2.4 и разрешение
`AllowOverride`.

## Production-конфигурация

Production-конфигурация — это значения и данные конкретного сайта, которые
нельзя безусловно заменять при обновлении:

- `root/data/config/*.php`;
- контент, меню, галереи, блоки и snippets;
- загруженные изображения и файлы;
- кэш, журналы и резервные копии.

На сервере следует включить `display_errors=Off`, `log_errors=On`, HTTPS,
действительный сертификат, OPcache и внешние регулярные резервные копии.
PHP-код snippets выполняется с правами PHP-процесса, поэтому редактирование
snippets должно оставаться доступным только доверенным администраторам.

## Обновление

1. Сохраните полную резервную копию, особенно `root/data`, `root/uploads`
   и `root/data/storage/backups`.
2. Проверьте обновление на staging-копии.
3. Перезапишите файлы приложения и assets. Не заменяйте рабочие
   `root/data/config/*.php` файлами `*.dist.php`.
4. Не перезаписывайте контент, snippets, меню, галереи, uploads и storage.
5. Сравните новые `*.dist.php` с рабочими конфигами и вручную добавьте новые
   параметры.
6. Запустите проверки и откройте основные страницы сайта и админки.

Каталог `sources/` содержит внешние справочные материалы. Он не должен входить
в публичный дистрибутив и загружаться на сервер.

## Проверки

Из корня репозитория:

```powershell
.\scripts\test.ps1
php tests/smoke.php --production
```

Первая команда проверяет синтаксис PHP и JavaScript, защитные маркеры и
целостность структуры контента, локальные asset-ссылки и базовые регрессии.
Режим `--production` дополнительно проверяет расширения PHP, HTTPS-адрес и
production-окружение.

Smoke-тест подтверждает, что основные части системы запускаются и данные
согласованы. Регрессионные тесты дополнительно фиксируют поведение отдельных
сценариев: сохранения, удаления, авторизации, SEO и других функций. Их набор
будет расширяться вместе с CMS.

Для локального запуска:

```powershell
.\scripts\start-server.ps1
```

Встроенный сервер PHP предназначен только для разработки. Он не применяет
Apache-правила из `.htaccess`.
